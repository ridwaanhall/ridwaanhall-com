{% load guestbook_tags %} {% comment %} One guestbook message and, recursively, its replies. This is the only definition of a message's markup. It used to exist twice -- once here in Django and once as a template-string literal in guestbook.html's inline script, for messages posted over AJAX -- and the two had to be edited together or new messages rendered differently until the next page load. SendMessageView now renders this same file and returns the HTML, so there is one copy again. Context: `message` (an enriched dict from GuestbookView, threaded by apps/guestbook/tree.py), plus `user` and `current_user_profile` for the action buttons. The rails are drawn by the wrapper around each reply below, not by the reply itself, so this file stays agnostic about where in a thread it sits. Geometry matches comments/_section.html -- left-[1.125rem] is the centre of a 2.25rem avatar -- with a tighter indent, because a comment thread nests once and this nests twice. {% endcomment %}
